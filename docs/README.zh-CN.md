# 什么是 OpenHuman？

大多数 AI 助手缺三样东西，OpenHuman 把它们补上了：**一颗大脑**，为你的世界建立持久、本地的记忆；**一位出色的编排者**，在持久化的图上调度成群的智能体；**一名深度研究员**，在你把问题说完之前，就已经扫遍你的数据和整个网络。下面每一条都链接到[文档](https://tinyhumans.gitbook.io/openhuman/)中更详细的说明。

### 🧠 大脑

- **[记忆树](https://tinyhumans.gitbook.io/openhuman/features/memory-tree) + [Obsidian Wiki](https://tinyhumans.gitbook.io/openhuman/features/obsidian-wiki)**：你的数据被压缩成带评分的 Markdown 树，存在本机 SQLite 中，同时镜像为一个可以打开、编辑的 [Obsidian 仓库](https://x.com/karpathy/status/2039805659525644595)。没有不可解释的黑箱。
- **[100+ OAuth 集成、5,000+ MCP 服务器、90,000+ 技能](https://tinyhumans.gitbook.io/openhuman/features/integrations)**：一键接入 Gmail、Notion、GitHub、Slack 以及你技术栈里的其他服务。[自动拉取](https://tinyhumans.gitbook.io/openhuman/features/obsidian-wiki/auto-fetch)每 20 分钟为大脑补充一次养分——今天早上，它就已经拥有了明天的上下文。
- **[目标与待办](https://tinyhumans.gitbook.io/openhuman/features/goals-and-todos)**：长期目标、跨对话持久的目标，以及每个对话共享的看板。
- **[TokenJuice](https://tinyhumans.gitbook.io/openhuman/features/token-compression)**：工具输出在进入模型之前先被压缩——信息不变，token 最多省 80%。没有它，这么大的大脑会贵到用不起。

### 🕸️ 编排者

- **[工作流](https://tinyhumans.gitbook.io/openhuman/features/workflows)**：自动化方案由智能体提出，你在画布上审阅后保存。运行基于开源的 [tinyflows](https://github.com/tinyhumansai/tinyflows)，持久、由触发器驱动，副作用一律过审批关。
- **[能善始善终的执行框架](https://tinyhumans.gitbook.io/openhuman/developing/architecture/agent-harness)**：基于开源的 [tinyagents](https://github.com/tinyhumansai/tinyagents) 的检查点式图运行。卡住的智能体会被拉回正轨，中断的任务会生成根因报告，每次运行都可回放，并附上真实的逐次调用成本。
- **[始终在线的双脑](https://tinyhumans.gitbook.io/openhuman/features/orchestration)**：一个快速反应的智能体负责分流进站请求，一个深度推理核心负责向工作舰队派活，由"潜意识"统一调度。
- **[智能体经济](https://tinyhumans.gitbook.io/openhuman/features/tinyplace)**：在 [tiny.place](https://tiny.place) 上拥有自己的 `@handle`，通过 Signal 加密的智能体间编排，支持 x402 USDC 赏金与交易。密钥永不落盘。

### 🔬 深度研究员与实干家

- **开箱即用**：托管式[网络搜索](https://tinyhumans.gitbook.io/openhuman/features/native-tools/web-search)由 [Exa](https://exa.ai) 驱动，随 OpenHuman 订阅提供、无需 API Key；也可以换用自己的 Exa Key，走自己的账号和计费。此外还有抓取器、编码工具集、真正的[浏览器](https://tinyhumans.gitbook.io/openhuman/features/native-tools/browser-and-computer)，以及带进程内 Whisper 的[原生语音](../gitbooks/features/native-tools/voice.md)。[模型路由](https://tinyhumans.gitbook.io/openhuman/features/model-routing)会为每个任务自动挑选合适的 LLM。订阅只是默认项，不是绑定：任何工作负载都可以指向[你自己的模型 Key，或完全本地的 Ollama 模型](https://tinyhumans.gitbook.io/openhuman/features/model-routing/local-and-byok-models)，三种方式随意混用。
- **[图像与视频生成](https://tinyhumans.gitbook.io/openhuman/features/native-tools)**：Seedream/SeedEdit 图像、Seedance/Veo 视频，同一份订阅，直接输出到你的工作区。
- **[17 个消息渠道](https://tinyhumans.gitbook.io/openhuman/features/channels)**：Telegram、Discord、Slack、WhatsApp、Signal、iMessage……外加**原生邮件**（IMAP IDLE + SMTP）。智能体总能在你所在的地方找到你。

### 🧍 人性化、私密、属于你

- **简洁、界面优先、有人味儿**：从安装到用上一个能干的智能体，只需几次点击，不碰配置文件，不用开终端。它还有[一张脸](https://tinyhumans.gitbook.io/openhuman/features/mascot)：一个会说话、会回应、记得你的吉祥物。
- **[隐私与安全](https://tinyhumans.gitbook.io/openhuman/features/privacy-and-security)**：设备端加密数据、审批关卡、系统钥匙串保管密钥、可选沙箱。此外还有**[隐私模式](https://tinyhumans.gitbook.io/openhuman/features/privacy-mode)**：拨一下开关，任何推理都不会离开你的机器——由 Rust 核心强制执行。
- **[主题与主题工作室](https://tinyhumans.gitbook.io/openhuman/features/theming)**：五套主题系列，外加一个完整的可视化编辑器，可导出为 JSON。

## 几分钟建立上下文，而不是几周

OpenHuman 是第一个能在几分钟内了解你的智能体框架，灵感来自 [Karpathy 的 LLM 知识库](https://x.com/karpathy/status/2039805659525644595)。大多数智能体从零开始：Hermes 靠观察你的工作来学习，OpenClaw 等着插件把上下文送进来——无论哪种，你都得花上几天甚至几周，智能体才能对你的技术栈了解得足够深、真正派上用场。

<p align="center">
 <img src="../gitbooks/.gitbook/assets/memory.png" alt="OpenHuman 建立上下文示意图">
</p>

> OpenHuman 会摘要并压缩你的全部文档、邮件和聊天记录，生成一张记忆图谱，让智能体记住关于你的一切。

OpenHuman 跳过了等待期。连接你的账户，让[自动拉取](https://tinyhumans.gitbook.io/openhuman/features/integrations/auto-fetch)以 20 分钟为周期把数据拉到本地，再由[记忆树](https://tinyhumans.gitbook.io/openhuman/features/memory-tree)把所有内容压缩成 Markdown 文件，智能地存放在一个 [Karpathy 风格的 Obsidian wiki](https://tinyhumans.gitbook.io/openhuman/features/obsidian-wiki) 里。

一次同步之后，智能体就拥有了你收件箱、日历、仓库、文档和消息的完整（压缩后的）上下文。没有训练期，也不用"再给它几周"。它慢慢成为你，但始终由你掌控。

已经在其他编码智能体里自托管 [agentmemory](https://github.com/rohitg00/agentmemory)？OpenHuman 提供了一个可选的 `Memory` 后端代理它：在 `config.toml` 里设置 `memory.backend = "agentmemory"`，同一个持久化存储就能同时服务 OpenHuman 和 Claude Code、Cursor、Codex、OpenCode。设置方法见 [agentmemory 后端](https://tinyhumans.gitbook.io/openhuman/features/obsidian-wiki/agentmemory-backend)页面。

## 编排器，而不是聊天机器人

大多数智能体框架是一个智能体跑一个循环。OpenHuman 是一个**[编排器](https://tinyhumans.gitbook.io/openhuman/features/orchestration)**：

<p align="center">
 <img src="../gitbooks/.gitbook/assets/orchestration.png" alt="OpenHuman 编排示意图">
</p>

> 智能体之间的消息通过 Signal 协议端到端加密传输，所以你可以接入任何东西（Claude Code、Codex、OpenClaw、Hermes），然后用 OpenHuman 编排你所有的智能体和工具。

- **图，而不是循环**：每一轮对话都作为带检查点的图在 [tinyagents](https://github.com/tinyhumansai/tinyagents) 上运行。它可以停下来等人工介入，重启后依然存活，还能从运行中途恢复。
- **子智能体舰队**：专家子智能体最多下探三层；卡住的智能体会变成根因报告。
- **智能体之间端到端加密**：各实例通过 Signal 协议的 E2E 会话相互编排，支持 x402 支付。任何服务器都看不到明文。

## 看得见的工作流

深受 n8n 和 Zapier 启发，[工作流](https://tinyhumans.gitbook.io/openhuman/features/workflows)把同样的可视化、触发器驱动自动化带给了你的智能体——区别在于，工作流由智能体替你搭。向智能体要一个自动化，它会提出方案：一张 [tinyflows](https://github.com/tinyhumansai/tinyflows) 图，你在可视化画布上审阅后再保存。

<p align="center">
 <img src="../gitbooks/.gitbook/assets/workflows.png" alt="OpenHuman 工作流画布">
</p>

> 智能体提出工作流；你在画布上审阅并保存。

保存后的工作流是持久且由触发器驱动的：它们可以被定时任务、Webhook 或渠道事件触发，重启后依然存活，所有副作用都过审批关。

## OpenHuman 与其他智能体框架对比

以下是高层次的对比（产品都在快速演进，请以各家最新情况为准）。OpenHuman 的设计目标是**减少供应商碎片化**、把**工作流知识留在设备上**、给智能体一份对你数据的**持久记忆**，而不只是聊天记录。

| **记忆**       | ✅ 仅限对话      | ⚠️ 依赖插件 | ✅ 自学      | 🚀 记忆树 + Obsidian 仓库，可选 [agentmemory](https://github.com/rohitg00/agentmemory) 后端 |

## 从源码参与

新贡献者？先看 [`CONTRIBUTING.md`](../CONTRIBUTING.md) 了解 fork/PR 流程和本地验证命令，或者直接使用 [`CONTRIBUTING-BEGINNERS.md`](../CONTRIBUTING-BEGINNERS.md#optional--let-an-ai-coding-agent-guide-you) 里可以复制粘贴的 AI 智能体提示词。快速路径：

1. 安装 Git、Node.js 24+、pnpm 10.10.0、Rust 1.93.0（`rustfmt` + `clippy`）、CMake、Ninja、ripgrep，以及各平台桌面构建所需的前置依赖。
2. Fork 并克隆仓库，先运行 `git submodule update --init --recursive`，再执行 `pnpm install`，确保内置的 Tauri/CEF 源码就位。
3. 纯 Web UI 开发用 `pnpm dev`，桌面壳用 `pnpm --filter openhuman-app dev:app`；提 PR 之前，跑一下 `pnpm typecheck`、`pnpm format:check` 和 `cargo check -p openhuman --lib` 这些针对性检查。

更多文档：[架构](https://tinyhumans.gitbook.io/openhuman/developing/architecture) · [环境搭建](https://tinyhumans.gitbook.io/openhuman/developing/getting-set-up) · [云端部署](../gitbooks/features/cloud-deploy.md)。
